# Architecture

RepoTray uses a Svelte 5/TypeScript panel and a Tauri 2/Rust desktop service. There is no application server or webhook service.

```text
Svelte panel ── typed commands and snapshots ── Rust live service
                                                ├── GitHub REST API
                                                ├── OS credential store
                                                ├── SQLite metadata/cache
                                                ├── Tray and notifications
                                                └── In-app update (verified NSIS installer, or signed Tauri updater)
```

The module-level diagram is [ARCHITECTURE.mmd](ARCHITECTURE.mmd) (Mermaid).

## Module structure

**Panel (`src/`).** `App.svelte` is the orchestrator: it wires the app bar, the panel body, dialogs, keyboard shortcuts and the update timer. Data and mutations live in controllers under `src/lib/`, so dialogs keep only form state and closing one never drops a running operation's result or busy state:

| Controller               | Responsibility                                                                                                                                                                                                                      |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `panel.svelte.ts`        | Snapshot, active account, refresh, templates and account disconnect; owns `Starts`, `Notices` and `Favorites`                                                                                                                       |
| `starts.svelte.ts`       | Workflow starts per target, independent of any dialog; uncertain outcomes stay locked until an explicit release                                                                                                                     |
| `notices.svelte.ts`      | Banner notices, one per key; plain success notices close after 3 s, notices with an action keep their own timeout and pause while hovered or focused (`NoticeBanner`), none closes while a dialog is open, warnings and errors stay |
| `favorites.svelte.ts`    | Heart toggles, removal with **Rückgängig**, quick starts and the focus moves they need                                                                                                                                              |
| `view.svelte.ts`         | Which page the body shows (the overview or a maximized section), the search query, the Verlauf filter, and where focus returns on minimize                                                                                          |
| `modals.svelte.ts`       | Which dialog is open, its initial settings tab (Konten, App, Updates) and seed, and where focus returns                                                                                                                             |
| `dispatchForm.svelte.ts` | Start-dialog form state: target, typed inputs and favorite fields                                                                                                                                                                   |
| `updater.svelte.ts`      | Update check and one `install_update` call (download, verify, install) with progress stages; state read-only from outside                                                                                                           |
| `autostart.svelte.ts`    | Windows autostart while Settings is open: reads the OS state, stages the switch, writes it on **Speichern**; repair actions act at once                                                                                             |

`src/lib/ipc.ts` is the only module that invokes native commands: `call()` is typed by a `Commands` map of every command registered in `generate_handler!` (`src-tauri/src/desktop.rs`) with its camelCase arguments and result, and `channel()` wraps streamed messages such as download progress. The contract test `src/lib/ipc.contract.test.ts` pins that map to `generate_handler!` in both directions and fails if any other file under `src/` imports or calls Tauri's `invoke`. `bridge.ts` selects native IPC (through `ipc.ts`, plus the `repotray:snapshot` event subscription) or the browser demo (`demo.ts`). `clock.ts` provides one shared minute clock (`minuteClock`) for relative run times and running durations, so rows own no timers; `shortcuts.ts` maps key presses to panel shortcuts (refresh, Ctrl+1/2/3 to maximize a section, search, Escape) and suppresses webview reloads. `safeGitHubUrl.ts` accepts exactly the run links the shell will open and builds repository page links only from GitHub-valid names. `autoRepos.ts` is the demo's copy of the automatic repository rule (`auto_repos.rs`). Pages and dialogs are components under `src/lib/`: `PanelBody` switches between the `Overview` (sections with a `SectionHeader` each: `LiveRuns`, `FavoriteTiles`, `RepositoryList` with a `RunStrip` per repository from `recentRuns` in `runs.ts`) and a maximized page whose section toggle stays in place (`SectionPage` renders only that header; `ActivityView` as the Verlauf, `FavoritesPage`, `ReposPage`); `FavoriteTiles` is the one favorites list on the overview and the Favoriten page, see [ADR-0002](adr/0002-single-overview-with-maximizable-sections.md) and [ADR-0005](adr/0005-maximize-toggles-in-place.md); each repository row has a `RepoMenu` („⋯“); the repositories themselves are automatic ([ADR-0003](adr/0003-automatic-repositories.md)); `SettingsDialog` and `DispatchDialog` share the `Modal` shell, which uses `focus.ts` for focus trapping and restoration. `SettingsDialog` stages its tabs (`AccountsTab` with `ConnectedAccounts`, `ThemeSetting`, `StartupSettings`, `UpdatePanel`) behind one **Speichern**. The connection dialog is `NativeConnect` natively (steps: `ConnectMethods`, then `LocalAuth` with `LocalAccountImport`, or the token form with `TokenPermissions`) and `ConnectPanel` in the demo; `BrowserAuth` is mounted nowhere while browser sign-in is paused. `StatusBanners` shows the update banner and the notices (`NoticeBanner`). `focus.ts` also names each page's focus landing (`landing()`: the search field on the overview, the page title on a maximized page). Styles live in ordered files under `src/styles/`, imported through `src/styles/index.css`; every color is a token in `00-tokens.css` with a dark and a light value. `theme.ts` keeps the **Darstellung** preference (System, Hell, Dunkel) in `localStorage` and sets `data-theme` on `<html>` before the panel mounts; „System“ is plain `prefers-color-scheme` CSS.

**Rust core (`src-tauri/src/`, crate `repotray_core`).**

| Module                                | Responsibility                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `live.rs` + `live/`                   | Native engine `LiveStore`: `transport` (HTTPS with a vault-backed bearer token), `connect` (add/remove accounts), `refresh` (catalog, metadata and run orchestration), `schedule` (per-scope timers, holds on unauthorized accounts), `catalog` (repository and ref listings, automatic selection through `auto_repos`), `dispatch` (claimed, exactly-once starts) |

| `browser_auth.rs`                     | Dormant GitHub App device flow                                                                                                                                                                                                                                                                                                                                     |
| `workflow.rs`, `models.rs`            | Bounded workflow YAML metadata parsing; the IPC data model                                                                                                                                                                                                                                                                                                         |
| `startup.rs`                          | Platform-independent Windows login-startup rules                                                                                                                                                                                                                                                                                                                   |
| `updates.rs` + `updates/installer.rs` | Update policy: release check, installer asset and digest validation, signed-update validation; `installer` downloads from GitHub hosts only, verifies size and SHA-256 and stages the EXE in `%TEMP%`                                                                                                                                                              |
| `run_link.rs`                         | Canonical GitHub Actions run URLs (`https://github.com/<owner>/<repo>/actions/runs/<id>`); shared test vectors with the panel in `fixtures/run-links.json`                                                                                                                                                                                                         |
| `popup.rs`                            | Physical-pixel popup geometry                                                                                                                                                                                                                                                                                                                                      |
| `demo.rs`                             | Local simulation on `fixtures/demo.json`, used by Rust tests                                                                                                                                                                                                                                                                                                       |

**Desktop shell (`src-tauri/src/`, binary `repotray`, feature `desktop`).** `main.rs` starts `desktop.rs`, which registers IPC commands, runs blocking work on worker threads, emits snapshots and manages the tray. Its `open_run` command opens only the canonical string returned by `run_link::canonical_run_url`, never the raw IPC argument, and rejects anything else. `desktop_auth.rs` holds the account commands (token, gh import, browser sign-in, cancel, disconnect), `desktop_startup.rs` the Windows Run-value adapter for autostart, `desktop_updates.rs` the update commands (`check_update`, `install_update`), and `tray_popup.rs` / `tray_popup/windows.rs` the window lifecycle and Win32 integration.

## Runtime boundaries

`live.rs` and its submodules own authenticated GitHub access, accounts, repository discovery and the automatic repository set, workflow definitions, refs, dispatch and polling. Frontend state never owns a persisted token. Tokens remain in the native OS credential store; SQLite and browser preferences contain only nonsecret data.

`src/lib/types.ts` and Rust models define the snapshot/command contract with camelCase JSON. The browser demo uses the same shapes with `fixtures/demo.json`. Its fictional identities and repositories are local examples, not discovered accounts. The sign-in preview is explicitly simulated. A real token entered into the native connection form is verified before native storage; unavailable secure storage has no plaintext fallback.

## Native sign-in, account selection and popup

`browser_auth.rs` implements the server-free GitHub App device flow and vault refresh rotation, gated by public publisher build configuration. `local_auth.rs` discovers gh CLI/GCM accounts and imports only an explicitly selected compatible gh credential; GCM discovery remains metadata-only. Native commands do not expose credential values to the frontend. See [browser authentication](BROWSER_AUTH.md) and [local authentication](LOCAL_AUTH.md).

`accountSelection.ts` persists the selected stable nonsecret credential ID. Selection lives in the account menu and Settings; same-login credential sources remain distinct and missing selections require a conscious choice. See [account selection](ACCOUNT_SELECTION.md).

The Windows popup tracks the actual tray rectangle and physical monitor work area, with its geometry isolated in `popup.rs` and native tray integration in `tray_popup.rs`. See [Windows popup validation](WINDOWS_POPUP_VALIDATION.md).

## Launch and cache safety

The panel starts on the overview: **Läuft gerade**, **Favoriten** and **Repositories** (ordered by the latest run update), each capped and maximizable to a full page. Repository disclosures expose workflow configuration, start buttons and heart favorites. The **Verlauf** is a flat history with open runs first and up to 50 completed runs; **Favoriten** reuses account-bound launch templates. A heart saves default-branch/default-input configurations without enabling quick start. Missing required inputs open the template form; customized variants remain separate.

Only workflows exposing `workflow_dispatch` on their default branch are eligible. YAML is parsed as data, refs are checked, inputs are typed and validated, and read-only repositories cannot launch. Pins retain account, owner/repository, workflow, ref and validated nonsecret inputs.

The UI locks pending dispatches and rejects stale responses after target/account changes. The native service persists a target claim before dispatch and quarantines ambiguous responses rather than blindly resending a POST. An uncertain target stays locked until the user explicitly releases it with the `release_uncertain_start` command; no code path releases it automatically. Claims persist across restart, are listed in the snapshot as `uncertainStarts` and are removed when their account is deleted. Closing a dialog does not dispatch. A successful acknowledgement identifies the exact run; it does not establish build success.

The GitHub transport serializes requests, constrains pagination to the GitHub API origin, handles ETags/304 and rate-limit backoff, and never automatically retries an uncertain dispatch. Polling focuses on the automatic repository set (10 latest pushed per account plus favorites' repositories) and slows when idle, offline or limited. Notification baselines avoid replaying historical failures at startup.

`run_history.rs` seeds the latest 50 runs per tray repository once per process. Later polls discover active runs and runs created since the last successful discovery, including short runs that already finished. A known open run missing from the active lists is resolved by its exact ID; absence and network errors never imply completion. Completed metadata remains unchanged, and completed IDs receive no further individual status requests. Active reruns can reopen a known ID. The cache retains all open runs and at most 50 completed runs per repository; the UI applies its 50-entry completed limit across repositories. Moving discovery-window pages are not retained in the ETag cache.

Use REST version `2026-03-10`. Dispatch responses include the exact run ID; legacy/malformed responses stay uncertain. See [GitHub connection](GITHUB_SETUP.md) and the [official dispatch API](https://docs.github.com/en/rest/actions/workflows#create-a-workflow-dispatch-event).

## Desktop and updates

The stable app ID is `io.github.fo0.repotray`. The webview loads local assets under a restrictive CSP, with no general shell capability; `src-tauri/capabilities/default.json` grants the panel window only snapshot event listening and header dragging (the double-click maximize toggle is granted but inert, because the window is not maximizable). Closing the panel keeps it in the tray; **RepoTray beenden** in the tray menu exits the process. Optional Windows login startup uses a guarded per-user Run value as its source of truth. The `--autostart` launch path keeps the already-hidden window hidden; a duplicate login launch leaves the existing instance alone. See [Windows startup](WINDOWS_AUTOSTART.md). Global hotkeys remain follow-up work.

Updates are independent of account selection (`updates.rs`, `desktop_updates.rs`, `src/lib/UpdatePanel.svelte`; [ADR-0004](adr/0004-in-app-updates-for-unsigned-builds.md)). Standard unsigned builds read the public `releases/latest` API on `api.github.com` without a token (at startup, every 6 hours, after connecting an account and on **Nach Updates suchen**), accept only a newer stable release whose `RepoTray_<version>_x64-setup.exe` asset carries GitHub's `sha256` digest and size, download it over HTTPS (redirects only to GitHub hosts) with progress over an IPC channel, verify size and SHA-256, write the EXE to `%TEMP%\RepoTray-update-<version>\`, run it passively (`/P /R /UPDATE`, current-user, no `/ARGS`) and exit; the installer restarts the app without `--autostart`, so its panel opens. Builds compiled with an updater public key use the official Tauri updater behind the same `install_update` command: `updates.rs` enforces stable versions, newer-than-current ordering and the exact repository/version-bound EXE URL, and the signature is verified before installing. See [release process](RELEASES.md).
