# UX checks and reproduction

The panel is designed for quick tray access at 360–480px widths. One app bar holds the brand, the account menu, refresh and settings (below 400px the brand keeps only its icon), the footer shows the connection status and the data's time, repository identities wrap instead of being discarded (favorites keep one line: the repository name shortens, the full name is in the tooltip, branch and account stay readable), and active runs appear before historical activity.

## Panel behavior

The panel opens on one overview without tabs (ADR-0002): **Läuft gerade** (running, queued and waiting runs as compact rows with status icon, workflow and repository, branch and elapsed time; **Gerade läuft nichts.** when idle), **Favoriten** as two tiles per row (name and repository, branch chip, a round start button and a heart that removes; at the 360 px minimum each tile is about 164 px wide and long names shorten with the full text in the tooltip) and **Repositories** (sorted by latest activity, one row each with `owner/` dimmed, the workflow count, the status as icon and text (open runs first: **2 aktiv** while several are open, else the open or latest run's status), **Nur Lesen** or **Kein Zugriff** where starts are not allowed, and a strip of the last 8 runs, newest on the right; empty cells where fewer runs exist and a running cell that pulses unless reduced motion is requested; the strip is an image whose label sums it up, e.g. „Letzte 8 Runs: 6 erfolgreich, 1 fehlgeschlagen, 1 läuft“; disclosures are keyboard accessible and stay open when a section is maximized; at the 360 px minimum the workflow count is left to assistive tech). Each section is a region named by its heading, with a count and a maximize button (**Strg+1/2/3** in its tooltip). The overview shows at most 3 running runs, 4 favorites and 6 repositories; **+N weitere** opens the maximized page, and an active search lifts the caps and filters every section. Without an account or selected repositories the overview names only that next step: **GitHub-Konto verbinden**, **Konto wählen** (opens the account menu) or **Repositories auswählen** (opens the picker).

A maximized page — **Verlauf**, **Favoriten** or **Repositories** — keeps its header with **Zurück zur Übersicht** above the scrolling body. Opening one moves focus to its title; going back returns focus to the control that opened it, else to the section's maximize button. A click on a running run, a notice's **Im Verlauf anzeigen** and the start result's **Im Verlauf anzeigen** open the **Verlauf** unfiltered with that run expanded and focused. Workflow rows and start buttons open configuration; heart favorites persist across reloads and remain account-bound; removing one offers **Rückgängig** for a few seconds, which restores label, inputs and quick-start mode. The **Verlauf** defaults to all runs, with open work followed by the latest completed history. Run times read relative (**gerade eben**, **vor 3 Min.**, **vor 2 Std.**, **gestern**, then the date) from one shared minute clock, with the exact time in the tooltip; each row offers opening the run on GitHub and **Link kopieren** without expanding. The running-now rows are deliberately no live region: the demo refreshes every second.

Repositories are managed in the panel, never in settings. **+ Hinzufügen** at the Repositories section or page, and the empty overview's **Repositories auswählen**, open the page **Repositories im Tray** (its search field takes focus; the way back returns to the page and control that opened it): every repository of the connected accounts grouped by account (avatar letter, login, label), each row with `owner/` dimmed, its access (**Schreibzugriff**, **Nur Lesen**, **Kein Zugriff**) and a button that reads **Im Tray** with a check or **Hinzufügen** and whose accessible name starts with that text (label in name, WCAG 2.5.3), e.g. „Hinzufügen: owner/name“; no `aria-pressed`, since its visible text changes with the state, and the footer **Änderungen gelten sofort – kein Speichern nötig.** A toggle applies at once and shows a spinner until the snapshot confirms it; quick toggles in a row are sent as one more call. Each confirmed change offers **Rückgängig** for a few seconds, which flips only that repository; a 51st repository is refused with a notice before anything is sent, and a refused change warns and shows the real selection again. Groups of an account that is not shown say when their repositories appear. A fresh connection lands on this page with a banner naming the login. While a search is active, the overview and the Repositories page list matching repositories outside the tray under **Nicht im Tray** (natively the active account's only); one click adds it, and it moves to the list above with focus on its row. Each repository row has an icon-only **⋯** button (also on right click or the context-menu key) with **Letzten Run auf GitHub öffnen** (only when a run exists; through the shell natively, disabled without a valid link), **Link kopieren** (the repository's GitHub page, checked against GitHub's name rules; disabled in the demo) and **Aus Tray entfernen** (with **Rückgängig**; focus moves to the neighbouring row). The menu uses the same keys as the account menu and stays inside the panel, opening upwards near the bottom.

The account menu in the app bar switches the active account directly: arrow keys, **Home** and **End** move through its entries, **Esc** closes it and returns focus to its button, **Tab** or a click outside closes it. It also offers **Konto verbinden …** and **Konten verwalten …**.

Keyboard shortcuts: **F5** or **Ctrl+R** refresh the panel (a webview reload is always suppressed), **Ctrl+1/2/3** maximize **Repositories**, **Verlauf** and **Favoriten** and the key of the open page returns to the overview, **/** focuses the search. **Esc** works in order: it clears the search, then leaves it; an open menu or dialog closes first; otherwise a maximized page returns to the overview. Refresh and section shortcuts also work from the search field; while a dialog is open, the dialog owns the keyboard. The search field's **Tastenkürzel** hint lists them.

A disabled start button names its one reason as tooltip and accessible description, the most basic cause first: **Kein manueller Start**, **Kein Schreibzugriff auf dieses Repository**, **Offline – Starts sind deaktiviert**, **Zugriff verweigert – Starts sind deaktiviert**, **Start läuft …** or **Startstatus ungeklärt – prüfe die Runs auf GitHub**. A running start locks only its own target in every list.

An uncertain dispatch stays locked across dialog reopening and app restart. Its warning has hover, focus and touch details; Escape and outside interaction dismiss the help without enabling another start. Only **Sperre aufheben…** releases the lock, after the confirmation **Ich habe die Runs auf GitHub geprüft – Sperre aufheben**; it releases exactly the lock shown when the confirmation opened and never starts anything. Saving a template during dispatch and pressing Enter in a template name cannot start another run.

Success notices close on their own after a few seconds, but not while hovered or focused; a notice that arrives behind a dialog waits until the dialog closes. Warnings and errors stay until closed. Dialogs trap Tab and Shift+Tab and close with Escape; closing returns focus to the control that opened them, and a chained dialog returns focus to the opener of the first dialog. A start result receives focus when it appears.

Body text is 14px and metadata never goes below 12px. Colors come only from the design tokens in `src/styles/00-tokens.css`: a dark set, and a light set that applies when the OS prefers light or **Einstellungen → App → Darstellung** says **Hell** (**Dunkel** keeps the dark set on a light OS; **System** follows the OS live; the choice is stored per device in `localStorage` and applied before the panel mounts). In both themes text, metadata, the accent and every status color meet WCAG AA (at least 4.5:1) on the panel, card and hover surfaces, status text also on its own tint, and text on the accent; `src/lib/tokens.test.ts` checks those pairs and forbids color literals anywhere else. Buttons, links and fields show a 2px focus ring that rows inside clipped containers draw inset, and Windows High Contrast (forced colors) redraws switches, the selected settings tab and filter, the live dot, menu item focus, filled favorite hearts, the round start of a favorite tile, status icon tiles, the **Im Tray** toggle (drawn like a selected tab), the chosen **Darstellung** option, the run strip (success as text color, failure as Mark, running as Highlight, other runs as a ring, empty cells as a grey ring) and tinted focus rings with system colors (`src/styles/14-forced-colors.css`).

Unit tests (`src/lib/*.test.ts`) cover the model, run lists, formatting, account selection, the panel controller, the page state (`view`), starts and start reasons, favorites, the repository selection (`repoSelection`: coalesced calls, cap, undo, fallback), notices, shortcut and menu key mapping, the demo, the run-link parser against `fixtures/run-links.json` and the repository link check, the IPC contract, the theme preference (`theme`) and the design tokens (`tokens`: AA contrast in both themes, no color literal outside the token file). Standard unsigned builds run a notify-only update check: the panel announces a newer stable release and opens only its release page, without downloading or installing anything. Separately configured signed builds download inside the app and install only after a second confirmation.

## Optional screenshots

```sh
pnpm dev
# In another terminal:
pnpm exec playwright install chromium
node scripts/capture-review.mjs
node scripts/capture-card-review.mjs
node scripts/capture-navigation-review.mjs
```

Capture scripts assert demo mode, fail on any request that leaves the dev server and exercise only synthetic local fixtures; each runs once with the OS preferring dark and once preferring light, and every file name ends in `-dark` or `-light`. `REVIEW_BASE_URL` points them at another dev server port. Output under `docs/review/` is ignored. Review captures before sharing; screenshots and browser profiles are not part of the source distribution. No existing private review material is included in the repository.

The review capture walks the demo (overview, Verlauf, account switch, favorites and the start dialog, picker, offline, missing rights, uncertain start, empty search, **Darstellung**, the GitHub connection preview with the demo token) into `docs/review/screenshots/` with `docs/review/manifest.json`. The card capture writes favorite cards, the uncertain-start help and the overview tiles with layout metrics to `docs/review/card-revision/`. The navigation capture writes the overview, every maximized page, the picker, the account menu and the settings App tab at 480×760 and the overview at 360×560 to `docs/review/navigation/` (`NAVIGATION_REVIEW_DIR` and `NAVIGATION_REVIEW_PREFIX` redirect them).

## Native acceptance

Browser checks cannot establish Windows tray placement, multi-monitor/DPI behavior, sleep/resume, OS notifications, credential-manager behavior or an installed application's lifecycle. Those need a native Windows acceptance session; see the [native Windows smoke checklist](VALIDATION.md#native-windows-smoke-checklist). Platform support beyond Windows requires equivalent testing.
